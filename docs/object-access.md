# Authored object access

Optional WorldProject.objectAccess uses schema elsemesh.object-access/1 and rules of objectId plus actions. Ordinary computers and canonical retro terminal anchors support computer.use; neon signs support neon.power and neon.configure. Unknown fields, duplicate rules/actions, unsupported actions and dangling objects are rejected. Empty rules explicitly deny every action.

Only an absent field uses version 1 legacy defaults derived from supported declarations. The inspector labels this mode. Use explicit rules deliberately snapshots those defaults; changing one checkbox also snapshots existing supported defaults before changing that action. Newly created objects do not acquire rules in an explicit policy.

These portable world rules are a ceiling. Every live player, including the owner playing as a visitor, still requires a separate private runtime grant from the owner. No player list, key or grant belongs in authored content. Vehicle permissions are outside this bounded version.

Exports declare object-access/1 so older readers reject this contract. Explicit policies are hash covered in the version 3+ connections snapshot component, alongside terminal declarations. Legacy packages without this capability remain readable only when objectAccess is absent. Full project/workspace saves preserve the field. Copy/paste remaps policy targets and canonical terminal anchor/screen references for copied objects.

## Welcome greeting

Optional welcome uses schema elsemesh.world-welcome/1, text (1–2000 characters, with no unsupported control characters), and audio (boolean). The world settings editor trims surrounding whitespace when leaving the text field; clearing it removes the greeting. Text is ordinary literal text, with no URL fetching or HTML execution. A present greeting requires welcome/1 on exports and is hash covered in connections.json. Read aloud requests the visitor browser voice. Private first arrival history is never authored into the world.
