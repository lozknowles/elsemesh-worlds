# Reusable Original Island object gates

## PLAN gate
Trigger: multi-source asset extraction, editor integration and public release. Architect reviewed the approach before implementation. Findings: reuse the six portable Original Island GLBs; derive static whale/bird/crab models from pinned game source; keep stable asset and entity IDs distinct; water/shore/air placement defaults; non-solid wildlife; provenance/licence; per-model and project budgets; save/reopen, visual and published-path checks. Primary accepted those conditions and kept engine weather and wildlife animation outside this static catalogue slice.

## NO-PROGRESS gate: preparation script
Trigger: worker observed the same JavaScript SyntaxError twice while regenerating the wildlife models. Architect found a syntax-level problem, recommended checking the script before more regeneration, and no architecture change. Worker corrected the apostrophe, node --check passed, two regenerations gave identical SHA256, and all 14 GLBs passed portable admission.

## NO-PROGRESS gate: browser startup
Trigger: MSI Edge twice showed a blank builder when opened over http://100.125.120.114:5205/. Architect directed a page error/secure-context check before another UI attempt. The captured error was crypto.randomUUID is not a function on that insecure HTTP origin. SSH localhost forwarding was administratively prohibited. An isolated browser test profile marked only this HP origin secure for local client verification; the published Pages origin is HTTPS and requires its own verification. No product graphics setting or source was changed for this test setup.

## NO-PROGRESS gate: native preview navigation
Trigger: fixed-duration W presses produced inconsistent camera travel and one position-poll timed out during video framing. Architect advised measuring frame progress, delivered keys and collision before changing navigation. Primary instead used the existing authored spawn X/Z controls to establish the whale viewing position and Return to spawn, then ordinary mouse drag for the beach view. The published preview rendered both locations. No navigation code was changed, and the diagnostic gap does not affect the static catalogue acceptance.

## COMPLETION gate
Trigger: review before declaring the library, publication and video complete. Architect found a finite-water placement bug: candidate selection checked depth but not the rectangular water extent. Primary added a model-bounds-aware extent check and a small-water rejection regression, then reran all 233 tests, lint (0 errors; one pre-existing React hook warning) and production build. Architect also found the first video's hut clicks were not framed on the new huts; primary re-recorded with Frame selected after each placement and visually checked the resulting hut frames. A combined whale-and-hut repository pack/reopen test now verifies the two portable model references and authored transforms together.

Published evidence: builder main d9beeb3 and Pages editor commit 4cd17dc (from builder d9beeb3) were confirmed remotely before the finite-water follow-up. The public HTTPS editor served the whale GLB with HTTP 200 and loaded Original Island at pinned commit 21a8a591. MSI Edge WebGPU native preview showed the placed whale in the sea and the new huts on the beach. The replacement MP4 at D:/Downloads/ElseMesh-whale-beach-huts.mp4 is 128.24 seconds, H.264 1600x900 at 25 fps, fully decoded by ffmpeg, and four sampled frames including close-up hut placements were inspected.

Scope limits: these are static reusable scenery assets; whale swimming, bird flight, crab movement and boat controls are engine behaviours not included here. Automatic placement is an editable starting transform and may need adjustment along an arbitrary shoreline. Exact save/reopen of the entire Original Island native closure with the demo additions and standalone game runtime admission were not physically verified in this release; the source-based combined-asset repository test and builder native preview cover the bounded library task.
